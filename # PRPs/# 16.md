# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives
When a user visits the app for the first time (or resets presets to default), the carousel in `src/components/SequenceSelector.tsx` currently displays **"Gentle Micro-Tuning"** (`['1', 'b2', '1', 'b3', '1']`) as the leftmost default preset[cite: 5]. 

We must insert a new primary default preset named **"Surround the Tonic"** with the scale degrees `['1', '2', '1', '7v', '1', '1']` at the first position (index `0`) of the `DEFAULT_SEQUENCE_PRESETS` array so that it serves as the default entry point and initial selection for new sessions[cite: 4, 5].

## 2. Technical Decisions & Dependencies
* **Preset Schema & ID Allocation:**
  * `id`: `'surround_tonic'`
  * `name`: `'Surround the Tonic'`
  * `degrees`: `['1', '2', '1', '7v', '1', '1']`
* **Array Ordering:**
  * Place the new preset at index `0` of `DEFAULT_SEQUENCE_PRESETS` in `src/components/SequenceSelector.tsx`, pushing all existing presets (`micro_tuning`, `sub_tonic_dip`, etc.) one index to the right[cite: 5].
* **LocalStorage Persistence & Cache Awareness:**
  * Because `src/App.tsx` initializes `selectedPresetId` and `presets` via `usePersistentState`, any browser with an existing cached session in `localStorage` will continue loading its previously stored array until the user clicks **Reset** or clears local storage[cite: 4].
  * The TDD checkpoint and user verification steps must explicitly include clearing `localStorage` or triggering `onResetDefaults` to verify the fresh first-visit state[cite: 4, 5].
