# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives
In the interactive piano keyboard (`src/components/PianoKeyboard.tsx`), two UI/UX visual defects disrupt the user experience during pitch calibration:
1. **Missing White Key Separation Outlines:** White keys currently blend together into a solid white block without crisp dividing lines between adjacent keys. Individual keys lack distinct borders, making it difficult to quickly identify note boundaries at a glance.
2. **Layout Shift from Peak Sinus Notification Banner:** When selecting a root note within the 130–150 Hz range (C3 to D3), the green **Peak Sinus NO Zone** notification card dynamically mounts *above* the piano keyboard container. This shifts the keyboard downward when the card appears and upward when a non-resonance note is selected, breaking spatial memory and distracting the user.

---

## 2. Technical Decisions & Dependencies
* **Crisp White Key Outline Specification:**
  * To restore clear visual delineation between adjacent white keys without causing horizontal layout shifts or double-border thickening, apply a uniform 1px solid border around every white key: `border border-slate-300`.
  * For active and root note states, replace border-width changes with `ring-2 ring-inset` or maintain an identical 1px border (`border border-cyan-500` / `border border-amber-400`) paired with an inner box shadow (`shadow-[inset_0_0_0_1px_rgba(...)]`) so the outer box-sizing remains identical across all selection states.
* **DOM Order Relocation of the Peak Sinus Banner:**
  * Move the conditional rendering block `{isResonanceZone && (...)}` from immediately *above* the 2-octave keyboard container (`<div className="relative w-full h-36 ...">`) to immediately *below* it.
  * Adjust spacing utility classes from `mb-3` to `mt-3 mb-0` so the card expands downward into the bottom padding of the component card without displacing the keyboard controls or key positions.
