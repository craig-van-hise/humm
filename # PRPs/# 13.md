# Product Requirements Prompt (PRP) — 🔘 Pending

## 1. Project Context & Objectives
The previous refactor successfully stabilized the React dependency graph and stopped the audio dropouts, but it introduced a initialization bug. Because we instructed the `initEngine` function to initialize the `Tone.Gain` nodes to `0`, and the volume-updating `useEffect` does not re-trigger when the session starts (since the volume state hasn't changed since the initial mount), the audio starts completely silent. 

**Objective:** Fix the silent initialization bug by ensuring `initEngine` constructs the Tone.js nodes using the actual current state values upon startup, rather than relying on the side-effect `useEffect` to correct them post-initialization.

## 2. Technical Decisions & Dependencies
*   **Comprehensive State Ref:** We will expand the `stateRef` pattern to capture *all* dynamic properties (volumes, waveforms, filter frequencies).
*   **Direct Initialization:** `initEngine` will read from this `stateRef` at the exact moment of AudioContext creation, ensuring all Gain nodes and Oscillators start exactly where the user's LocalStorage or pre-session tweaks left them.

## 3. Implementation Phases

### Phase 1: Comprehensive State Tracking & Initialization Refactor — ✅ Completed

        ```typescript
        // Bundle all props into a single object for easy tracking
        const propsRef = useRef(props);
        useEffect(() => {
          propsRef.current = props;
        }); // No dependency array = tracks latest props on every render
        ```
