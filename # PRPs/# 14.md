
# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives
The 17-key / 2-octave interactive piano keyboard (`PianoKeyboard.tsx`) currently exhibits three UI/UX defects:
1. **Misaligned Black Key Proportions:** Black keys are dynamically positioned at the exact 50/50 percentage seam between white keys (`((whiteIndex + 1) / totalWhite) * 100`). On an acoustic piano keyboard, black keys are unequally offset relative to the seams between white keys (e.g., C# is shifted left, D# is shifted right, G# is centered). Furthermore, a flex container `gap-[2px]` causes cumulative pixel drift between the white key seams and the absolute percentage positions of the black keys.
2. **Layout Shift / Re-drawing on Selection:** Selecting a different key dynamically adds a `border-2` class to keys that previously had no border (`border-0`), causing flexbox items to recalculate their widths and visually jitter/redraw note proportions.
3. **Octave Selector Default:** The visual keyboard octave defaults to Octave 3 (`getOctave` fallback and initial state). Because the Peak Sinus Nitric Oxide (NO) resonance zone targets $130\text{ Hz} - 150\text{ Hz}$ ($C_3 - D_3$), the keyboard octave selector must default to **Octave 2**, displaying Octaves 2 and 3 ($C_2$ through $B_3$) so $C_3$ sits centered in the viewport.

---

## 2. Technical Decisions & Dependencies
* **Acoustic Piano Key Offsets (12-Tone Equal Temperament Geometry):**
  In a standard octave of 7 white keys ($100\%$ octave width), black keys do not sit at the exact midpoint of white key seams. We define a constant lookup table for black key percentages within a single octave:
  * `C#`: `13.5%` *(shifted left of the C/D seam at 14.28%)*
  * `D#`: `29.3%` *(shifted right of the D/E seam at 28.57%)*
  * `F#`: `55.8%` *(shifted left of the F/G seam at 57.14%)*
  * `G#`: `71.43%` *(centered on the G/A seam at 71.43%)*
  * `A#`: `87.0%` *(shifted right of the A/B seam at 85.71%)*
* **2-Octave Absolute Positioning Formula:**
  With 14 white keys total across 2 octaves, each octave represents `50%` of the container width. The absolute left percentage for any black key is:
  $$\text{leftPercent} = (\text{octaveIndex} \times 50) + (\text{BLACK\_KEY\_OCTAVE\_OFFSETS}[\text{noteName}] \times 0.5)$$
  * **Octave 0 Black Keys:** `C# = 6.75%`, `D# = 14.65%`, `F# = 27.90%`, `G# = 35.715%`, `A# = 43.50%`
  * **Octave 1 Black Keys:** `C# = 56.75%`, `D# = 64.65%`, `F# = 77.90%`, `G# = 85.715%`, `A# = 93.50%`
* **Zero-Layout-Shift Sizing & Border Normalization:**
  * Remove `gap-[2px]` from the white keys container. Instead, apply `border-r border-slate-300 last:border-r-0` to white keys so flex columns divide $100\%$ container width identically without gap-induced coordinate drift.
  * Enforce a permanent `border-2` on all keys at all times (`border-2 border-transparent` for inactive white keys, `border-2 border-slate-800` for inactive black keys). Changing selection state will only toggle the border color (`border-cyan-500` / `border-amber-400`), preventing layout reflow.
  * Give black keys an explicit, fixed width of `"4.3%"` of the container width ($\approx 60\%$ of a single white key's $7.14\%$ width).

     ```ts

     keys.forEach((note, idx) => {
       const isBlack = note.includes('#');
       if (isBlack) {
         const name = note.replace(/\d+$/, '');
         const octaveIndex = idx < 12 ? 0 : 1;
         blackKeys.push({ note, name, octaveIndex });

     });
     ```

     Set the inline style to:
     ```tsx
     style={{
       left: `${leftPercent}%`,
       transform: "translateX(-50%)",
       width: "4.3%",
     }}
     ```
  4. In the white keys container `<div className="flex w-full h-full ...">`, remove `gap-[2px]` so that flex columns align with absolute percentages.
