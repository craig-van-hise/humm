# Product Requirements Prompt (PRP) — 🔘 Pending

## 1. Project Context & Objectives
The recent implementation of the dynamic Tone Settings Modal successfully wired UI controls to the `useAudioEngine` state, but it introduced audio dropouts. Using Tone.js's `.set()` method or deeply updating the node tree during active playback is causing the Web Audio API nodes to momentarily dispose of or reset their connections, resulting in the drone pads disappearing and the guide melody dropping out mid-sequence. 

**Objectives:**
1.  **Seamless Real-Time Tweaking:** Refactor the `useEffect` in `useAudioEngine.ts` to use direct property mutations (e.g., `.type = newType`) rather than `.set()`. This alters the waveform seamlessly without stopping the oscillator or rebuilding the node.
2.  **Guide Tone Filter:** Introduce a new lowpass filter dedicated to the Guide Tone Melody so its warmth/brightness can be sculpted in the same manner as the drone pads.

## 2. Technical Decisions & Dependencies
*   **Tone.js Mutation Logic:** To safely change waveforms on the fly, we will explicitly mutate the oscillator properties (`osc.type = newWaveform` and `synth.oscillator.type = newWaveform`). Filter frequencies will continue to use `filter.frequency.rampTo(newFreq, 0.1)`.
*   **Audio Graph Addition:** A new `Tone.Filter` will be inserted between `guideSynthRef.current` and `guideGainRef.current`.
*   **State Expansion:** A new state variable, `guideFilterFreq`, will be added to `App.tsx` and the `ToneSettingsModal`.

## 3. Implementation Phases

### Phase 1: Engine Refactor & Guide Filter Routing — ✅ Completed
*   **Objective:** Prevent audio dropouts during state changes and add the guide tone filter node.
*   **Instructions:**
    1.  Open `src/hooks/useAudioEngine.ts`.
    2.  Add `guideFilterFreq: number;` to the `AudioEngineProps` interface.
    3.  Create a new ref for the guide filter: `const guideFilterRef = useRef<Tone.Filter | null>(null);`.
    4.  In the `initEngine` function, instantiate the filter and update the guide synth routing:
        ```typescript
        // New guide filter (default to lowpass)
        guideFilterRef.current = new Tone.Filter(1000, "lowpass").connect(guideGainRef.current);
        
        guideSynthRef.current = new Tone.Synth({
          oscillator: { type: "triangle" },
          envelope: { attack: 0.08, decay: 0.1, sustain: 0.85, release: 0.15 },
        }).connect(guideFilterRef.current); // Connect to filter instead of gain directly
        ```
    5.  Rewrite the dynamic update `useEffect` block to directly assign types instead of using `.set()`, which prevents the nodes from resetting:
        ```typescript
        // 6. Dynamic Tone Adjustments
        useEffect(() => {
          if (!isEngineInit.current) return;

          // Mutate directly. Check current type to avoid redundant assignments
          if (droneRootOscRef.current && droneRootOscRef.current.type !== droneRootWaveform) {
            droneRootOscRef.current.type = droneRootWaveform;
          }
          if (droneRootFilterRef.current) {
            droneRootFilterRef.current.frequency.rampTo(droneRootFilterFreq, 0.1);
          }

          if (droneFifthOscRef.current && droneFifthOscRef.current.type !== droneFifthWaveform) {
            droneFifthOscRef.current.type = droneFifthWaveform;
          }
          if (droneFifthFilterRef.current) {
            droneFifthFilterRef.current.frequency.rampTo(droneFifthFilterFreq, 0.1);
          }

          if (guideSynthRef.current && guideSynthRef.current.oscillator.type !== guideWaveform) {
            guideSynthRef.current.oscillator.type = guideWaveform;
          }
          if (guideFilterRef.current) {
            guideFilterRef.current.frequency.rampTo(guideFilterFreq, 0.1);
          }
        }, [droneRootWaveform, droneRootFilterFreq, droneFifthWaveform, droneFifthFilterFreq, guideWaveform, guideFilterFreq]);
        ```
    6.  Ensure `guideFilterRef.current?.dispose();` is added to the cleanup `useEffect` at the end of the file.
