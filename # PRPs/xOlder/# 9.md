# Product Requirements Prompt (PRP) — 🔘 Pending

## 1. Project Context & Objectives
Previous implementation phases successfully resolved the audio desynchronization and deprecated the redundant `PitchPicker` component. This PRP isolates the final remaining UI flaw: the `PianoKeyboard` usability issues. 

Currently, the keyboard dynamically shifts its octave layout when higher or lower fundamental pitches are selected, causing disorientation. Additionally, the octave switch incorrectly alters the fundamental pitch instead of just the visual layout. 

**Objective:** Decouple the keyboard's visual view from the fundamental pitch state. The octave switch must *only* change the visual layout, and clicking keys must *only* change the fundamental pitch (`rootNote`) without triggering an automatic visual shift.

## 2. Technical Decisions & Dependencies
* **Static Keyboard Logic:** `PianoKeyboard.tsx` will utilize a localized React state (`keyboardOctave`) to manage a fixed 2-octave layout. This isolates the visual grid from the global `rootNote`, preventing automatic redraws when selecting notes that exist in different octaves.
